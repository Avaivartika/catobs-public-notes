来自ICML OpenAI RL 负责人 Noam Brown 分享，以下为转录对话。

## 一、核心要点（TL;DR）

1. **CoT 可解释性**：RL 中加 length pressure 提升 token 效率后，CoT 可解释性意外地没有明显退化；OpenAI 明确不因“坏念头”惩罚模型（只罚行为、不罚思想），并倡议这应成为行业标准——否则模型会学会隐藏坏念头。
    
2. **Scaling 路线**：现有范式（pretraining + RL / 可验证任务扩展）仍有大量空间，团队认为现有方法足以达到 AGI；同时也在探索其他架构和训练范式。倾向于先推到“自动化研究员”，再由其发现更优技术。
    
3. **长 horizon 的最大瓶颈是 infra 和评估**：模型 rollout 已从秒级推进到小时 / 天 / 周级（o1 → GPT-5.5 / 5.6），未来评估一个模型可能比训练一个新模型还耗时；METR 和 UK AISI 均反馈周级任务评估的瓶颈就在 infra 稳定性。
    
4. **能力信号**：模型已在数学上超越顶尖人类（解决 / 推进 Erdős 相关问题），下一个大概率是药物发现方向。
    
5. **自动化研究员**：Noam 表示如果现在要在“人类 AI 研究实习生”和 GPT-5.6 之间选，他会选 5.6（5.5 也成立）；衡量自动化研究的首选指标是“人们愿意在无监督情况下分配给 Codex 多少 GPU”。
    
6. **未来三年最重要的三个问题**：① 对齐（system card 中 misalignment 指标清零）；② 样本效率（进入物理科学需再提升一个数量级）；③ 长 horizon 下的上下文优先级管理（类人记忆取舍）。

## 1. CoT 可解释性与 length pressure

**问：** RL 中的 length pressure 提升了 token 效率，是否会导致 CoT 偏离可解释的语言？

**Noam Brown：** 坦言“很惊讶这至今没有成为问题”——模型思考更高效的同时保留了大量可解释性，预计该趋势会延续。如果 RL 做得足够久，理论上可能最终漂移到不可解释，但按目前观察到的速度，可预见的未来内不会发生。

**团队成员：** 模型本就在“人类可理解的语言”上训练，要把 CoT 压到不可读需要非常大的压力，目前远没到那个程度。且随着任务越来越 agentic，中间大量 tool call 本身就提供了对模型意图的可观测性——即使是 10 小时的任务，也不会对模型在做什么毫无洞察。

**Noam Brown（关键立场）：** OpenAI 明确不惩罚模型“坏念头”，并倡导这应成为行业标准。已有研究表明：如果因坏念头惩罚模型，模型会学会以用户不可见的方式想坏念头。正确做法是罚行为、不罚思想，以此保留可解释性。

## 2. 通往开放式智能还缺什么 / 是否需要新的 scaling 轴

**问：** 达到真正 open-ended intelligence 还缺哪些关键能力？pretraining 红利耗尽后靠 RL + 环境扩展，下一层能力靠继续 scale 还是架构层面的根本变化？

**团队：** 不便展开内部进展，但认可“大家都能感受到模型哪里不行”。

**Noam Brown：** 还有大量空间继续 scale，进展很快且预期持续。同时 OpenAI 内部在积极探索其他范式，也鼓励社区探索——“现在有效的方法不代表是最好的或唯一的方法，很可能存在更好的架构和训练方式”。

**关键判断：** 他认为现有技术路径足以达到 AGI（截图中转录为 “sufficient to get into the gym”，应指 AGI）。倾向于继续推进现有路径直到得到“自动化研究员”，再由它去发现更好的技术。

**真实担忧：评估。** 现在评估耗时几秒到几分钟，部分长 agent 任务已需数小时；很快模型能连续运行数周甚至无限期，届时评估耗时可能超过训练一个新模型的时间，如何应对尚无答案。

## 3. RLVR 的局限：奖励稀疏 / 长 horizon

**问：** RLVR 在长 horizon 任务上受奖励信号稀疏所困，业界开始转向更复杂技术，怎么看 RLVR 的根本问题？

**Noam Brown：** 模型现在（如用 Codex）已经能连续运行数小时、数天甚至一周以上——“RLVR 能走到这么远其实挺出人意料的”。更好的 RL 技术很可能存在、能做得更好，但幅度未知；总体判断是现有方法仍有大量继续 scale 的空间。

## 4. RL 的下一步与对消费者的影响

更强的智能会层层传导到应用。模型已开始在部分科学领域超越顶尖人类——目前是数学（对 Erdős 相关问题 / 猜想给出了结果），很快会扩展到其他科学领域，药物发现被点名为“非常可能的下一个”，对消费者影响巨大。

**软件层面：** 更好、更快的软件，一切产品体验都会受益。

## 5. 多轮 agent 的 credit assignment

**问：** 多轮 agent 范式下 credit assignment 怎么解决？

**Noam Brown：** ICML 上已有大量相关论文，不想钦点某一种“正确技术”；解法很多，社区应该全面探索。现有技术已经走得很远且还能推得更远，但“这不是天花板，还能做得更好”。

## 6. 持续学习 / lifelong agent

**问：** 如何看 RL 通往像人类一样可无限运行、持续学习的 agent？

**团队成员：** 把 continual learning 拆开看——有些部分 RL 解决不了，但很多单项能力 RL 可以给到。

举例：人类非常擅长与“昂贵环境”交互（如药物发现中人体 / 动物实验次数极其有限，人类会在决定推进哪个候选药前做大量准备）。这种高样本效率的决策能力完全可以被表述为 RL 任务，可以预期模型在这上面变好。

---

## 7. 长 horizon RL 的痛点：infra

**问：** 当前长 horizon 任务最大的痛点是什么？

**团队成员：** infra 是被低估的环节。超长 rollout 对基础设施压力巨大：数据存储与搬运、维持高吞吐、防止崩溃等，都会影响下游训练。

**Noam Brown：** 近期与 METR 和 UK AI Safety Institute 都聊过，两家一致反馈：评估长时任务的瓶颈就是 infra——一个一周的任务要求 rollout 环境连续稳定运行一周，期间任何崩溃都是问题。

**团队成员（ML 侧）：** rollout 太长意味着单位时间信号更少、迭代更慢，拖累研究节奏。

---

## 8. 学术界 vs 工业界

**问：** 学术界在 RL / 长 horizon 研究上哪里做得不对？哪些事只有工业界能做？

学术界受算力限制只能训小模型，而很多好想法在小尺度上并不能很好地 scale（一位成员自述从 MIT 的 4 张 H200 到入职后的上千张）。对齐研究在 7B 级模型上很难做出有效结论——更大的模型更聪明，对齐相关行为才充分显现。

**重要平衡观点：** 即使在 OpenAI 内部，想法也都是先在小尺度验证再放大。“小尺度上 work 的新颖想法非常非常有价值”，之后只是多了一道“哪些能 scale”的过滤工序——小尺度成果的价值不应被贬低。

---

## 9. 通用模型 vs 专用模型能否“解决所有疾病”

**问：** 解决所有疾病靠通用大模型还是要训专用模型？是否存在“通用智能 → 解决生物学 → 数据反哺通用智能”的飞轮？

**Noam Brown（自谦非 bio 专家）：** 生物领域最难的是获取信号——临床试验动辄数年，与他们“快速迭代”的工作方式天然不匹配。但更强的模型辅助研究人员会带来显著加速。他认为最重要的能力是“找到瓶颈、加快迭代”，疾病领域同理。

**团队成员：** “通用 vs 专用”是伪二分法：既要构建对发现类任务同样有用的通用能力（如上下文的实验样本效率），也可以同时有专门团队去攻克“把模型应用到 discovery 的具体瓶颈”，两者并行不悖，OpenAI 内部就是这么做的。

---

## 10. CoT 变长变贵 + CoT 是否忠实反映思考

**问：** CoT 越来越长、越来越贵，是否可持续？以及看得见 CoT 不代表模型真的在“想”，是否考虑把推理移到 latent space？

**效率：** 观察 OpenAI 历次发布，都是在把智能-成本的帕累托前沿向“更高智能、更低成本”方向推。模型思考效率大幅提升——同样的 token 数，新模型给出的智能远超旧模型，且环境中存在飞轮效应。

**忠实性：** 承认“CoT 未必反映模型真实思考”是一个 valid concern，没有保证。缓解手段之一仍是“不惩罚坏念头”——不罚，模型就没有隐藏思考的动机。

## 11. 高价值任务与 outcome-based pricing

**问：** 最近谈到“单个任务价值 1000 万美元”，现在的算力能解什么任务？推理泛化的前沿在哪？

**团队成员：** 社会自然会为任务定价——有人愿意付 1000 万美元的任务就值得做。业界最近在讨论 outcome-based pricing：不按 token 计费，而是“给定任务，模型报价完成该任务所需成本”。极端例子：如果客户愿意为解决某问题支付 1 亿美元，“那能买下好几个数据中心，大概率能解决一个相当难的问题”。

**当前实例：** 模型已经发现（GPU / 算力相关的）效率优化——提到“我们用模型参与设计了自己的 GPU”（截图转录质量较差，此处存疑）。Erdős 问题实际求解成本很低，但换做 GPT-5.5 也许要花约 10 万美元量级的推理成本才能解出——取决于你多想解决它。

## 12. 长时 agent 的实践 playbook：评估与记忆

**问：** 构建长时 agent 有没有可复用的方法论？评估怎么做？要不要配层级化记忆系统？

**评估方法论（团队成员，原文以 eval 展开）：** 理想状态是“短 eval 完美泛化到长任务”，现实中很难。实操建议：

- 始终保留少量昂贵但直接对准目标行为的“金标准” eval，防止对小 eval 测不到的盲区视而不见；
    
- 只要小 eval 与大 eval 表现相关，就主要在小 eval 上快速迭代；
    
- 本质是在“更快的迭代飞轮”与“与目标行为完全对齐的评估”之间做 trade-off。
    

**记忆 / harness（Noam Brown）：** harness 有价值但过时得非常快。现在自建 memory 系统或许有用，但其重要性会随模型能力下降；“如果要搭 harness，别投入太多时间精力，三个月后大概率就过时了”。

---

## 13. Harness 会不会消失

**问：** RL 越 scale，harness 是否会越简单，工具是否会全由模型自己造？

**回答：** 是。以历史为例（早期检索类模型有大量自定义 embedding search 工具，后来都被模型内化）。模型越强，harness 越少 / 越薄——不是完全不重要，而是相对权重持续下降。

## 14. 是否主动瞄准公开数学 / 科学难题

**问：** 训练时是否有意瞄准数学 / 科学中的 open problems？

**Noam Brown：** 解决 Erdős 问题是副产品，不是目标。两个理由：

1. 团队时间应花在“把模型做得尽可能聪明、尽可能快地发布给所有人”，让全世界用模型去解决科学问题，而不是自己攥着模型解题；
    
2. 公平性：OpenAI 处于能优先接触模型的特权位置，“先用模型把所有 open problems 解完再发布给世界”对所有研究者不公平。
    

**例外情形：** 他们确实会解一些问题，出于：① 作为评估；② 向世界更新能力水位。解 Erdős 问题正是为了向外界展示模型达到了新的能力层级，且该能力具有代表性。很多现在就能解的问题即使解了也不会发布，因为不能提供新的能力信息增量。

## 15. 是否需要显式注入创造性 / 多样性思维

**问：** 是否需把创造力、多样化思考显式训练进推理模型？

**团队成员：** 主张结果导向——给模型多样化的任务集合并最大化解决率，创造力和通用智能会随之涌现。“什么算有创意”带有很强的人类先验 / 归纳偏置，不应把这种偏置灌进模型。若某任务确实需要多样性（如“给出 5 个方案”），可以在评估 / 奖励层面直接对多样性计分。对数学证明这类问题，解法有没有创意根本不重要——能解就行。

**Noam Brown（历史视角）：** Q*（Q-Star）出来时最令人惊讶的一点：业界曾花大量精力想把“回溯、多路径探索”烘焙进模型（当年 MCTS 的热潮正是为了引入多样性和不同策略），结果 strawberry 系列（o1）模型在 CoT 中自然而然地学会了这一切——没有任何人为注入，模型的创造性表现远超预期。

**追问：** 追问者以“同一道数学问题不同解法带来不同洞见”为例坚持多样性价值；Noam 回应：不认为现有方式就是最优解，值得探索各种替代方案。

## 16. 自动化研究员：进展、定义与度量

**问：** Sam 等提过今年秋天出“自动化研究实习生”，作为每天用这些工具的人，你们感觉进展如何？如何定义？

**Noam Brown：** 基于公开信息的最佳回答——GPT-5.6 的能力在他看来已匹配“研究实习生”的预期。“如果现在让我在人类 AI 研究实习生和 5.6 之间选，我选 5.6；说实话 5.5 也成立。”同时强调模型是 spiky 的：很多方面比人强（“比我强”），很多方面也更差，不是与人类的直接一一对应，但正在全面变好。

**团队成员（度量视角）：** 自动化研究没有干净的单一 metric。他心中最“无 harness”的开放定义：Codex 变得越来越强，可以给它越来越长的任务。首选度量：人们愿意在完全无监督的情况下给 Codex 分配多少 GPU。当前形态还是“模型做、人检查 / 人指挥”，不算 fully autonomous，预计会有机地爬坡直到大量工作被自动化。

**另一成员的定义：** 能端到端完成一个非平凡任务——从 idea 生成，到实验执行，到结果分析、得出结论和 next steps。

## 17. 自主迭代系统的“漂移”问题

**问：** autonomous iterative / self-improving 系统如何保证多轮迭代中不漂移、保持可靠？

**回答：** 现阶段之所以不担心漂移，是因为大量工作仍由人类验证——拿到结果要人工检查好坏。如果模型产出能做到始终一致可靠，才会是另一个故事；目前人为干预和检查环节还很重，还谈不上完全自主的 training agents。

## 18. 模型能否超出训练分布

**问：** 模型的能力来自训练，能否在推理 / rollout 中获得训练范式之外的新能力、新解法？

**Noam Brown：** Erdős 问题的结果就是相当直接的证据——这显然不在训练数据里，但模型解出来了，答案是 yes。

**追问：** “策略层面是否只是收敛到同一策略？”

**Noam Brown：** 再次给出结果导向的回答——“什么叫策略新颖”很难定义；如果模型解决了未解决的问题、做出了新的事情，他对“用的策略新不新”持不可知立场——新颖的结果本身就是他关心的全部。

## 20. 未来三年最重要的三个问题

**问：** 接下来三年 reasoning 领域最重要的三个问题？

1. **对齐（Noam Brown）：** 呼应上一问的 hacking——OpenAI 在 system card 中披露 misalignment 水平，“我想把那些数字降到零。彻底解决对齐非常重要，而它今天没有被解决。这是我的第一优先级。”
    
2. **样本效率（团队成员）：** 让模型从远更少的样本中学习。coding 和数学之所以是目前落地最深的领域，正因为采样便宜（代码可在环境里随便生成验证）；要进入物理科学等领域，样本效率需要再提升一个数量级。
    
3. **长时上下文的优先级管理（团队成员）：** 模型要能像人一样，在长时间跨度里判断哪些 context 最值得记住。

## 21. 可验证 vs 不可验证任务的差距：写作为例

**问：** o3 以来阅读、数学进步巨大，写作仍明显落后，这个 gap 能不能弥合？

**Noam Brown：** 差距更多归因于专注度和资源分配，而非本质障碍——“如果 OpenAI 全力去做（某个方向），它就会发生”。很多不可验证任务上模型其实已经很好。Deep Research 是第一个真正的存在性证明：报告好坏极难验证，但模型表现很好——说明“不可验证 / 难验证任务上取得好表现”是可行的。

## 22. 社会科学类问题：无标准答案、验证周期长

**问：** 政策制定者关心的“会不会通胀 / 衰退”这类问题没有可验证答案，RL / 推理模型如何在这类任务上持续进步？

**团队成员：** 这归入前述的长 horizon 评估元难题——“四年后有没有衰退”唯一的验证方式就是等四年。社会科学的验证 horizon 天然比其他领域长得多，是它们的头号挑战之一。

## 23. 收尾问题：auto-research 的 scaffold vs 模型原生长 horizon

**问：** 自动化研究目前是 step-by-step 实验，但在 meta-learning、符号推理、跨知识图谱远距离推理等“高层归纳”上还不行，差距在哪？

**Noam Brown：** 核心归结为 agent 的 operating horizon。现在可以用 scaffold 延长思考 / 测试时间，但过去几年模型原生运行时长被推进得非常快：o1 只能思考几秒 → 今天的模型轻松思考数小时甚至一天 → 预期推进到“数周”。到那时模型原生能力会比典型 scaffold 更有效。类比：o1 时代也有让模型跑超过 24 小时的 scaffold，缺陷很多；现在 5.5 / 5.6 原生就能有效运行超过一天。scaffold 现在暴露的短板会随模型进步自然消失。

- 长 horizon 任务中，如何构造既低成本又能外推到真实目标行为的 eval？
    
- 对“不可验证 / 慢验证”任务，是否存在可学习的代理指标，且不会被 reward hacking？
    
- 当 harness 的相对权重下降时，哪些工具能力会被模型内化，哪些仍需外部系统提供？
    
- 自动化研究员的度量是否应从“任务完成率”转向“可委托 GPU 预算”或“无监督运行时长”？
    
- 对齐研究是否需要在更大模型尺度上观察，才能捕捉真实的 misalignment 行为？
